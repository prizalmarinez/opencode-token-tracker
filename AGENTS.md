# AGENTS.md

Read-only telemetry dashboard for the local opencode SQLite database (tokens, cost, sessions). Vite + React 19 + TS + Tailwind frontend, plus a tiny node:sqlite API server. No tests, no CI.

## Commands
- `pnpm dev` — runs **three** processes via `concurrently -k`: `opencode serve` (:4096), the API server (:3100), and Vite (:5174). You almost always need all three.
- `pnpm typecheck` / `pnpm lint` — required before finishing a change. `pnpm build` (`tsc -b && vite build`) also runs typecheck. When running `pnpm lint`, always allow it — don't ask for confirmation.
- `pnpm format` — Prettier with `prettier-plugin-tailwindcss` (auto-sorts classes). Keep `semi: true`, double quotes.
- No test framework exists. Headless browser checks are done ad hoc with `playwright-core` from a temp dir.

## Dev server gotchas (the #1 failure mode)
- The API is a plain `node server/index.mjs` process with **no watch/restart** — after editing `server/*.mjs` (`index.mjs` or `query.mjs`), restart it. Editing frontend is fine (Vite HMR).
- `opencode serve` is a separate process with **no watch** either — the `/search` chat feature talks to it through the `/api/chat` proxy. If the frontend reports the opencode server offline, it's `opencode serve` that's down, not the API.
- **Stale processes cause `EADDRINUSE` / "Failed to fetch" in the browser.** Before restarting, clear leftovers: `pkill -f server/index.mjs; pkill -f vite; pkill -f "opencode serve"; lsof -ti:4096,3100,5174 | xargs kill -9`. Verify with `curl http://localhost:3100/health` and `curl http://localhost:4096/global/health`.
- Vite is **pinned to 5174** (`port: 5174, strictPort: true` in `vite.config.ts`) — if the port is taken, `pnpm dev` fails rather than bumping.
- Frontend errors like "Failed to fetch" almost always mean the API is down, not a code bug.

## Server (`server/`)
Split into a **query module** and a **thin HTTP adapter**:
- `server/query.mjs` — the deep module. Owns the real opencode DB **read-only** (`node:sqlite`, experimental flag in the `dev:server` script), the `session_base` TEMP VIEW, all prepared statements in `STMT_SQL`, and the per-path connection cache. Interface: `getOpen(path)`, `querySummary(stmts, scope?)`, `querySessions(stmts, {project, limit, offset})`, `queryStatus(stmts, dbPath)`, `queryProjects(stmts, scope?)`, `closeAll()`. Scoped variants are derived by injecting `WHERE project_name_key = ?` after `FROM session_base` (see `SCOPABLE`) — add new SQL as prepared statements in `STMT_SQL` only, never as ad-hoc query strings. **The view is the single source of truth for units and shapes**: it emits `time_created_ms` (epoch normalized once — `dateRange` and `sessions` must use it, never raw `time_created`), and all statements alias columns to camelCase so `querySummary` is a pass-through (no JS remap). `byProject` is uncapped; the client truncates for display.
- `server/index.mjs` — the HTTP adapter. Resolves the db path (`?db=` → `OPENCODE_DB` → default), checks CORS **once** at the top of the request, routes `/api/*` to the query module, serializes JSON. No SQL here. `MAX_LIMIT` here must stay ≥ `PAGE_SIZE` in `src/lib/api.ts`. **`/api/chat/**` is a streaming reverse proxy to `http://127.0.0.1:4096/**`** (`opencode serve`) — it pipes request+response bodies un-buffered so SSE (`/event`) streams, and accepts GET + POST + DELETE (session create/prompt/abort/delete); everything else stays GET-only. It's checked before the GET-only gate; add chat tooling there, never to the read-only query module.
- Default DB path `~/.local/share/opencode/opencode.db`.
- Endpoints: `/api/status`, `/api/summary` (with `?project=<project_name_key>`), `/api/sessions` (with `?project=` and `limit/offset`, limit capped at 500), `/api/projects` (project-overview rows for the projects page + command palette), `/health`, `/api/opencode-health` (proxies the opencode server's `/global/health` so the browser stays single-origin; always 200 — the `ok` field carries the truth, since the client's `request<T>` rejects non-2xx). Aggregation endpoints stream tiny result rows — never ship the whole session table to JS.
- DB is large (~1 GB+); filter server-side, don't pull all sessions client-side.

## Frontend architecture
- `@/*` aliases `src/*` (vite + tsconfig). No router library — pathname routing in `src/App.tsx` (`navigate()` in `src/lib/navigate.ts` does `pushState` + dispatches `popstate`): `/usage` (default; `/` and `/index.html` redirect here), `/projects`, `/status`, `/settings`, `/search`, `/project/<encodeURIComponent(key)>`, anything else → `NotFound`. Project rows link to `/project/...`; `parseProject()` decodes the key. `/search` is lazy-loaded (`lazy()` in `App.tsx`) and only routes when the `oct-show-search` setting is on (`useSearchVisibility()` in `src/features/settings/search-visibility.ts`).
- **Data fetching is one primitive**: `src/lib/use-query.ts` exports `useQuery(fetcher, deps)` (refetch when deps change, cancel on unmount, per-query error/loading) and `useAnyQueryLoading()` (drives the nav refresh spinner). `App.tsx` is the composition root: it owns `dbPath` and a `refreshKey` (the nav refresh bumps it), and each page composes its own queries through `useQuery` — `Usage` (`getSummary` + `getSessions`), `Projects` (`getProjects`), `SettingsPage` (`getStatus`), `StatusPage` (`getStatus` + `useOpencodeHealth`), `ProjectPage` (scoped `getSummary` + `getProjectSessions` for the neural net). Every prop a fetcher reads must be in its `deps`. Aggregation is server-side; never re-GROUP BY client-side. `src/lib/use-opencode-health.ts` polls `/api/opencode-health` (~15s, pauses when the tab is hidden) and drives the `StatusPip` + `/status` sparkline.
- **The `/search` feature is deep research, not a plain chat.** Every prompt is prefixed with `DEEP_RESEARCH_INSTRUCTIONS` (in `src/features/search/report.ts`) so the agent plans, runs `websearch`/`webfetch` across many sources, then emits ONE standalone HTML report wrapped in `REPORT_START_MARKER`/`REPORT_END_MARKER` (also defined there — the prompt and parser share the marker contract). `splitReport(text)` extracts the marked report (falling back to a ```html fence or a bare `<!doctype html>` doc) and returns the leftover narration text; `SearchPage.tsx` renders the narration as markdown and the report in a `ReportCard` — a sandboxed iframe (`sandbox="allow-scripts allow-popups"`, no `allow-same-origin`) with open-in-tab + download (blob, filename from `reportFileName`/`slugify`). It uses `@opencode-ai/sdk`'s `createOpencodeClient` pointed at `/api/chat` (`src/lib/opencode-client.ts`) and a second primitive `useSearchChat` (`src/lib/use-chat-stream.ts`) that owns one active session per thread (localStorage `oct-search-session`), a thread registry (localStorage `oct-search-threads` — the app's source of truth for which sessions are research threads, titled "deep research"), and subscribes to the SSE `/event` stream, accumulating `Part`s by `messageID` keyed by `partID` and flushing on `requestAnimationFrame`. It returns `{ messages, threads, busy, pendingPermission, error, send, abort, respondPermission, selectThread, newThread, deleteThread }`; permissions answer via `postSessionIdPermissionsPermissionId`. Switching threads swaps `sessionId` state so the load/subscribe effect re-runs. `SearchPage.tsx` is its composition root (model toggle from `config.providers()`, source chips from `webfetch`/`websearch` tool parts, thread sidebar, streaming markdown). **`/search` forces the sidebar nav layout regardless of the stored `oct-layout`** (`App.tsx` computes `effectiveLayout`), and the thread list renders *inside* that nav sidebar via a portal into the `SidebarSlotContext` slot (`src/lib/sidebar-slot.ts`); the slot div is `flex-1` + `overflow-hidden` and the thread list itself is `overflow-y-auto`, so it scrolls like a real sidebar. The SQLite DB is never used here — the opencode server is the backend.
- Pure leaf modules live in `src/lib/`: `format.ts` (formatters + `Range`), `share.ts` (`topWithOther` + `fmtShare`), `export.ts` (`exportReport` single interface, `EXPORT_MARKERS` for the DOM-capture contract), `api.ts` (fetch + `PAGE_SIZE`), `cn.ts`, `navigate.ts`.
- **Lint is strict**: `react-hooks/set-state-in-effect` (recommended config) errors on synchronous `setState()` in an effect body. Follow the existing pattern: wrap async work in an inner `run()` (see `src/lib/use-query.ts`). `noUnusedLocals`/`noUnusedParameters` are on in tsconfig — unused vars fail typecheck and `no-unused-vars` fails lint.
- Recharts 3: chart class names differ from v2 (e.g. `g.recharts-bar-rectangle`); custom tooltip uses `p.name` over `p.dataKey`. Charts cap at top 8 + an aggregated "other" slice; `src/features/usage/chart-colors.ts` is the shared palette.
- `lucide-react` here has no brand icons — the GitHub header icon is an inline SVG.

## Styling / tokens
- All colors are HSL CSS variables in `src/index.css` (`--background`, `--accent`, `--muted-foreground`, `--border`, ...) consumed via `hsl(var(--accent) / 0.5)`; Tailwind maps them (e.g. `text-accent`, `bg-muted`). Don't hardcode hex in components.
- Theme system: `<html data-theme>` override blocks in `index.css`; the app theme (localStorage key `oct-theme`, default ember/orange) is applied in `src/main.tsx` pre-render.
- `Card` root element's class is `card-surface` — not `rounded-lg`/`card` (a `cn()` merge of `"card-surface group relative overflow-hidden p-5"`). Don't rely on Tailwind class names to locate it.
- Font is IBM Plex Mono everywhere via `--font-mono`; classes like `num` (tabular figures) are defined in `index.css`.

## Misc
- Commits use conventional style (`feat:`, `fix:`, `docs:`, `refactor:`) — see `git log --oneline`. `.gitignore` excludes `dist`, `node_modules`, `.env*`.
- Env vars (`.env.example`): `OPENCODE_DB` (db path override), `OPCODE_SERVER_PORT` (API, default 3100), `VITE_API_URL` (defaults to `http://localhost:3100`); the server also reads `OPENCODE_CHAT_PORT` (opencode serve, default 4096).
- `CONTEXT.md` holds the domain glossary (session/project/summary wire names); `src/types/index.ts` mirrors the wire contract by hand. `README.md` is stale on routing (still says hash routing) — trust `src/App.tsx`.
- Never update a file inside `node_modules` — changes there are ignored by git and wiped on install. Fix the source or use a patch/override instead.
- Components are hand-rolled primitives in `src/components/ui/` (Card, Button, Badge, Input) — extend those rather than adding a UI dependency.
